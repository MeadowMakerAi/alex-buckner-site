FM Command

An operating system for a small company. It keeps one current record of the whole business and lets AI agents act on it when a person gives permission.

To addShort film: FM Command in three minutes, recorded with demo data

The problem

What a small company knows is scattered across email, texts, meetings and people's heads. Nothing stays current. The founder ends up as the person who updates everything by hand.

FM Command started as a simple project tracker for a building renovation. I kept extending it until it became the system I wanted: one that captures what happens, works out what is true, and moves work forward by itself where that is safe.

I'm not a software engineer. I designed the system, wrote the specifications, and directed AI coding agents to write the code.

How it works

The whole system is one loop with eight steps. The result of the last step becomes new evidence for the first.

Step 1

Capture

Email, documents, meeting notes and spoken debriefs come in as evidence.

Step 2

Claims

The system pulls out what each piece of evidence says happened.

Step 3

Reconcile

Conflicting claims are compared. The system states what it knows and what it is guessing.

Step 4

One record

Each fact is stored once. People, companies, projects, places and equipment are all linked.

Step 5

Context

Each person and each agent sees the part of the record their role allows.

Step 6

Attention

The system shows what needs a decision next, and who it is waiting on.

Step 7

Action

An agent proposes a change. A person approves it. The system carries it out.

Step 8

Verify

Every action is checked. The result goes back in at step 1.

Four decisions that shaped it

The easier a change is to undo, the less permission it needs

Changes that can be reversed in one step go straight in. Bigger ones need one yes for the batch. The most serious need a yes for each item. Anything learned from an email always waits for my approval.

Small builds, each with a written finish line

Every change is specified with tests a machine can run. The coding agent writes the code, runs the tests, checks the feature in a browser as a signed-in user, then ships it. Two AI systems review each other's work before anything merges.

Define it before it gets a screen

Nothing is bolted on. Each new thing is first defined: what it is, what it connects to, and who can see it. Then it gets a page.

Agents are simple teammates

Each agent is a written skill plus a schedule. That is easier to keep working than a separate agent platform, and every run leaves a record.

The ten rules it is built on

  1. Clear to anyone. Any screen makes sense without extra context.
  2. Picture first. Complex information is drawn before it is written out.
  3. Automate. If the system can do it, it should.
  4. Always a next step. Everything leads to something that can be completed.
  5. One machine. Every part is defined and connected before it gets a screen.
  6. Capture everything. Information comes in from every part of the business.
  7. Readable at a glance. Dense walls of text count as a defect.
  8. Show the source. Every fact traces back to where it came from, and guesses are labeled.
  9. One home for each fact. Everything else points to it.
  10. Fix the source. A repeated correction means the system is wrong, so the system gets fixed.

What didn't work

Approving every change one at a time

It was too slow to keep up with a real business. Permission by how reversible a change is replaced it.

A goal loop that ran by itself

It produced activity, not progress. I removed it.

Big builds that took weeks

They stalled. Now every build is a small slice that ships from start to finish.

Still hard: keeping the record current

Text messages and in-person conversations are not captured well yet. That is the open problem.
